Assisted deploy: one command with rollback, plus optional auto-deploy

You had to SSH in and run four commands (pull, build, up, check) for every
update, with no safety net if a build came up broken — one instance, no staging,
so a bad deploy is a live outage.

deploy/deploy.sh — one command
------------------------------
    cd ~/codeskate && ./deploy/deploy.sh

Does what a human forgets under pressure: checks whether anything actually
changed (no-op if not), tags the running image as a rollback point, builds and
starts the new one, then health-checks /healthz for ~60s — and if it never comes
up, relaunches the previous image and exits non-zero. Worst case is "still on the
old version", never "down". Detects docker compose v2 vs older docker-compose,
and caps the build at 400m so it cannot OOM the 1 GB box.

The app service now pins image: codeskate-app:latest so the rollback tags a known
name rather than one Compose derives from the working directory.

.github/workflows/deploy.yml — optional, fully hands-off
--------------------------------------------------------
Push to main and the instance deploys itself over SSH, running the same
deploy.sh (same rollback). Needs four repo secrets (SSH_HOST/USER/KEY/PORT),
documented in deploy/DEPLOYING.md. Skips docs-only pushes, serialises deploys so
two never overlap, and has a manual "Run workflow" button. Delete the file to go
back to manual — deploy.sh does not depend on it.

tests/test_deploy_script.sh drives deploy.sh against a bare git origin and fake
docker/compose/curl, covering all three paths — up-to-date, new-version success,
and health-failure rollback — 10 assertions, all passing. App suite unchanged
at 121.
